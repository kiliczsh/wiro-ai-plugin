# Model discovery and comparison
Use `search_models` for keyword/category/owner and `explore` for curated lists. Use `recommend_model` for goal-oriented ranking. Query relevant candidates; do not assume catalog availability. Compare model slug, task suitability, input/output types, required parameters, restrictions, estimated price, speed only if measured, and quality only if supported by evidence. Retrieve `get_model_schema` for finalists, using returned lowercase `owner/model` slugs. Never invent costs, benchmarks or parameter names. Prefer a compact comparison table and recommend by user priorities. Distinguish fixed prices, usage-dependent prices and unavailable quotes.
